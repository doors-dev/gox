## A Go language extension that makes HTML templates a first-class expression.

```
func Hello(name: string) gox.Elem {
    return <h1>
        Hello ~(name)!
    </h1>
}

// or

elem Hello(name: string) {
    <h1>
        Hello ~(name)!
    </h1>
}

```

* Seamless editor support: near-native language-server experience across .gox and regular .go files.
* Full templating toolbox: conditionals, loops, composition, and reusable components.
* Maximum flexibility: bring your own rendering pipeline and apply arbitrary post-processing — ideal for frameworks and tooling.
* Compatible with `templ`

---

## How To Install

### Set up your development environment

> Recommended: use the official [VS Code](https://github.com/doors-dev/vscode-gox) or [Neovim](https://github.com/doors-dev/nvim-gox) extension.

The editor extension is enough to get started. If you want the CLI tool or prefer a manual setup:

1. Download the `gox` binary from GitHub Releases and add it to your `PATH` (or build it from source).
2. Install the Tree-sitter grammar: https://github.com/doors-dev/tree-sitter-gox

#### Configuration

The editor extensions configure everything automatically. See their documentation for available options.

For manual setup:

1. Attach the GoX language server to both `.go` and `.gox` buffers (see `gox srv -help` for available options).
2. Disable the default Go language server (`gopls`). GoX starts its own `gopls` instance and proxies features while adding `.gox` support.
3. Ensure `gopls` is on your `PATH`, or configure a custom path for `gox`.

### Add the dependency to your project

```bash
go get github.com/doors-dev/gox
```

> Make sure your tooling version matches the Go package version and keep both up to date. Currently, the language server does not enforce this automatically.

## How To Use

Extended syntax is available in `.gox` files. 

The GoX language server compiles `.gox` files into `.x.go` files and keeps them up to date automatically whenever you save a `.gox` file in your editor.

> - If an existing `.x.go` file was generated by a newer version of GoX, the server will report an error until you upgrade.  
> - Orphaned `.x.go` files are deleted automatically. Avoid naming regular files with the `.x.go` suffix.

You can also trigger generation manually using the CLI:

```text
gox gen [flags]

  -force
        overwrite existing files without checking
  -no-ignore
        ignore .gitignore
  -path string
        file or directory to generate (default ".")
```

## Syntax

### 1. Element

An **element** is an HTML tag expression:

```gox
el := <div></div>
```

You can return it, pass it as a function argument, store it in a struct field, etc.

```gox
func Page(content gox.Elem) gox.Elem {
    return <html>
        <body>
            ~(content)
        </body>
    </html>
}

// call
Page(<h1>Hello!</h1>)
```

> You can also use an **anonymous wrapper tag**  to group content without adding an actual HTML element: `<>Hello</>`

#### `elem` function shorthand

`elem` is a shorthand for functions that return `gox.Elem`:

```gox
elem Page(content gox.Elem) {
    <html>
        <body>
            ~(content)
        </body>
    </html>
}
```

Anonymous functions are also supported:

```gox
page := elem(content gox.Elem) {
    <html>
        <body>
            ~(content)
        </body>
    </html>
}
```

…and methods:

```gox
type Component struct {
    content gox.Elem
}

elem (c *Component) Main() {
    <html>
        <body>
            ~(c.content)
        </body>
    </html>
}
```

> - `ctx` is available inside elements and provides a `context.Context`.  
> - Self-closing syntax works for any tag. For non-void tags, GoX will automatically emit a closing tag (`<div/>` → `<div></div>`).


### 2. Component

A **component** is anything that implements `gox.Comp`:

```go
type Comp interface {
    Main() gox.Elem
}
```

> For compatibility, `gox.Elem` also implements `gox.Comp`.

### 3. Placeholder

Insert values using a placeholder: `~(value)`:

```gox
<h1>Hello ~(name)!</h1>
```

You can also insert multiple values:

```gox
<h1>Hello ~(name, " ", surname)!</h1>
```

Any value type is supported (rendered using default formatting), with special handling for:

- `gox.Comp` / `gox.Elem`
- `templ.Component` (from `github.com/a-h/templ`)
- Slices such as `[]string`, `[]gox.Comp`, `[]gox.Elem`, `[]any` (rendered item-by-item)
- `gox.Job`, `gox.Editor` (covered below)

#### Advanced placeholder types

`gox.Job` allows writing directly to the output stream:

```go
type Job interface {
    Context() context.Context
    Output(w io.Writer) error
}
```

`gox.Editor` enables direct cursor manipulation (see Go docs for `gox.Cursor`):

```go
type Editor interface {
    Edit(cur Cursor) error
}
```

### 4. Conditions and loops

If / else-if / else are available as expressions:

```gox
<div>
    ~(if user != nil {
        Hello ~(user.name)!
    } else if loggedOut {
        Bye!
    } else {
        Please log in
    })
</div>
```

Loops:

```gox
~(for _, user := range users {
    <tr>
        <td>~(user.name)</td>
        <td>~(user.email)</td>
    </tr>
})
```

### 5. Attributes

#### Values

Use parentheses to provide a Go expression as an attribute value:

```gox
elem block(id: string, content: any) {
    <div id=(id)>~(content)</div>
}
```

Any value is accepted. If the value is `false` or `nil`, the attribute is omitted.

> Attribute names are case-sensitive! Always use the same case.

#### Advanced attribute behavior

During rendering, the default formatter is used unless the value implements `gox.Output`:

```go
type Output interface {
    Output(w io.Writer) error
}
```

To read and transform a previous attribute value, implement `gox.Mutate`:

```go
type Mutate interface {
    Mutate(prev any) (new any)
}
```

Implement `gox.AttrMod` to inspect or modify an element’s attributes right before it’s rendered:

```go
type AttrMod interface {
    Modify(ctx context.Context, tag string, attrs Attrs) error
}
```

To apply an attribute modifier, wrap it in parentheses and place it directly in the opening tag:

```gox
<button (LandingAction)>
    Request Demo!
</button>
```

### 6. Inline expression

An **inline expression** is a function literal evaluated immediately during rendering. Its return value is inserted exactly where it appears (node content or attribute value).

Use it for short local logic (branching, error handling, temporary variables) without extracting a separate component.

```gox
<div>
    ~func {
        user, err := Users.get(id)
        if err != nil {
            return <span>DB error</span>
        }

        return <div>~(Card(user))</div>
    }
</div>
```

In attributes, the same idea applies—the expression result becomes the attribute value:

```gox
<input type="checkbox" checked=func {
    user := Users.get(id)
    return user.Agreed // false or nil omits the attribute
}>
```

### 7. Code blocks and comments

To run Go code during rendering (without rendering output), use `~{ ... }`:

```gox
~{
    user := Users.Get(id)
}
<div>~(user.name)</div>
```

To comment inside templates, use `~//` or `~/* ... */`:

```gox
~// <div></div> - commented out
```

> HTML comments are also supported.

### 8. Proxies

A **proxy** captures an element subtree and can transform it before rendering. Apply a proxy by prefixing the target expression with `~>`:

```gox
~>(proxy) <div>
    Proxy can apply transformations to this HTML.
</div>
```

A proxy must implement `gox.Proxy`:

```go
type Proxy interface {
    Proxy(cur Cursor, elem Elem) error
}
```

> Proxies can reduce boilerplate, add integrations, or collect analytics. More details will be covered later.


## Rendering

GoX elements are compatible with `templ` and implement `templ.Component`:

```go
type Templ interface {
    Render(ctx context.Context, w io.Writer) error
}
```

If you want to preprocess output, analyze it, or parallelize rendering, implement a custom printer:

```go
type Printer interface {
    Send(j Job) error
}
```

Where `Job` is:

```go
type Job interface {
    Context() context.Context
    Output(w io.Writer) error
}
```

Then render via `Print(ctx context.Context, printer Printer) error`.

> Templates are compiled into a stream of meaningful `Job`s that you can post-process and handle in custom pipelines. More details are available in Go docs.
